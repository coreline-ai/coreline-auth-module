## 개발 목적

현재 `coreline-auth` 프로젝트 안에 예제 형태로 들어와 있는 게시판 도메인(`src/coreline_auth/examples/board_*`)을 인증 모듈에서 완전히 분리한다.

최종 목표는 다음 상태다.

- `coreline-auth`는 인증/세션/RBAC/MFA/OAuth/WebAuthn/운영 readiness만 제공한다.
- 게시판은 별도 폴더/패키지에서 `coreline_auth`를 외부 인증 라이브러리로만 사용한다.
- `src/coreline_auth`는 게시판 도메인 모델, 게시판 스토리지, 게시판 라우트, 게시판 seed, 게시판 권한 문자열을 직접 포함하지 않는다.
- 의존 방향은 항상 `coreline-board -> coreline-auth`이며, 반대 방향은 금지한다.

## 개발 범위

기본 권장 위치는 현재 패키지의 형제 폴더다.

```text
/Users/hwanchoi/project_202605/CoreMCP/packages/
├── coreline-auth/      # 기존 인증 프로젝트
└── coreline-board/     # 신규 게시판 프로젝트
```

단, `coreline-auth`가 독립 Git repository이고 상위 `packages/`가 workspace repo가 아니라면 `coreline-board`는 별도 Git repository로 시작한다.

포함 범위:

- 새 게시판 패키지/폴더 구조 설계
- 기존 게시판 도메인 코드 이동 계획
- 인증 프로젝트에서 게시판 의존 제거 계획
- 게시판 권한 정책 분리 계획
- 테스트/문서/CI 분리 계획
- 데이터베이스 분리와 선택적 마이그레이션 계획

## 제외 범위

- 실제 코드 이동/구현은 이 문서 작성 단계에서 수행하지 않는다.
- 새 게시판 기능 추가는 하지 않는다.
- UI 리디자인은 하지 않는다. 기존 board HTML 흐름을 그대로 보존한다.
- 인증 모듈의 보안 패치, OAuth, MFA, WebAuthn 기능 확장은 하지 않는다.
- CoreMCP 전용 adapter 구현은 하지 않는다.
- 게시판 production-grade 비동기/Postgres 전환은 이번 분리의 필수 완료 조건이 아니다. 단, 후속 Phase 후보로 경계만 열어둔다.

## 문서 기반 제약 사항

- `src/coreline_auth`는 `coremcp.*` 또는 `apps.api.coremcp.*`를 import하지 않는다.
- `coreline-auth`는 독립 인증 모듈이며 게시판은 인증 모듈의 하위 기능이 아니다.
- password/session/magic-link token 원문을 DB/log/audit에 저장하지 않는다.
- 자체 암호 알고리즘을 만들지 않는다.
- 분리 후 `coreline-auth -> coreline-board` 의존은 금지한다.
- 게시판은 인증 토큰을 저장하지 않고, `coreline_auth`가 검증한 세션/Principal/user_id/role만 소비한다.

## 핵심 설계 결정

### 1. 의존 방향

```text
coreline_board  ──imports──▶  coreline_auth
coreline_auth   ──must not──▶ coreline_board
```

게시판은 `CorelineAuthService`, `Principal`, `Role`, `AuthorizationDenied`, `AuthValidationError` 같은 공개 API만 사용한다.

### 2. 권한 정책 분리

현재 `coreline_auth.permissions.py`는 `board:read`, `post:create`, `comment:create` 같은 게시판 권한을 기본 역할 정책에 포함한다. 완전 분리 후에는 인증 코어가 게시판 권한 문자열을 몰라야 한다.

권장 방향:

- `coreline_board.permissions`에 게시판 권한 상수와 `board_permissions_for_role(role)`를 둔다.
- `BoardService`는 `principal.session.permissions`에 들어 있는 게시판 문자열에 의존하지 않고, `principal.session.role` 또는 주입된 resolver로 board 권한을 계산한다.
- `coreline_auth.permissions.py`에서는 board-specific permission을 제거하거나, 제거가 breaking이면 한 릴리스 동안 deprecated compatibility로만 둔다.

### 3. 데이터베이스 분리

현재 demo는 같은 SQLite 파일에 auth table과 board table을 함께 둘 수 있다. 완전 분리 후 기본값은 별도 DB다.

```text
coreline-auth demo DB:   .coreline-auth-demo/auth.sqlite3
coreline-board demo DB:  .coreline-board-demo/board.sqlite3
```

게시판 테이블은 `author_user_id`만 저장하고 auth user/email/session/token 원문은 저장하지 않는다.

### 4. Demo 분리

`coreline-auth`의 `saas_app.py`는 auth-only self-test app으로 축소한다. 게시판까지 포함한 통합 demo는 `coreline-board` 쪽에서 제공한다.

```text
coreline-auth/examples/saas_app.py       # 로그인, 세션, admin, readiness 등 auth 검증 중심
coreline-board/demo/app.py               # coreline_auth를 소비하는 게시판 통합 demo
```
