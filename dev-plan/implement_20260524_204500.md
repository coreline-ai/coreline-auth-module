# implement_20260524_204500.md

작성 일시: `2026-05-24 20:45:00 KST`

이 문서는 Coreline Auth R5 microscope audit에서 발견된 release-blocker와 GA 전 High 항목 중, 현재 Mac 환경에서 코드·테스트로 바로 검증 가능한 hardening 범위를 고정한다.

## 개발 목적
- SQLite 기반 MFA AAL2 persistence와 one-time token/recovery-code race를 차단한다.
- 인증 모듈이 audit/email sink 장애 때문에 core auth flow를 실패시키지 않도록 best-effort 경계를 둔다.
- CSRF 서명을 SHA-256 string hash에서 표준 HMAC-SHA256으로 바꾼다.
- 운영 health-check와 최소 logging/metric hook을 제공한다.
- R5 release-blocker blind spot을 회귀 테스트로 고정한다.

## 개발 범위
- SQLite/Memory/Postgres storage의 atomic login-flow consume contract.
- SQLite `auth_sessions.assurance_level` update 누락 수정.
- Recovery code used guard (`used_at IS NULL`) 적용.
- TOTP same-window replay 방지용 `last_used_counter` 저장.
- `CorelineAuthService` logging/metric sink, email/audit best-effort 처리.
- `AuthStorage.health_check()` 및 adapter 구현.
- R5 blocker 회귀 테스트 추가.

## 제외 범위
- Full distributed rate-limit backend 확장.
- WebAuthn/passkey full ceremony.
- Async admin/MFA/social full parity.
- Tenant/organization/billing 등 SaaS 제품 기능.
- 외부 SIEM/OTel exporter 직접 구현.
