# implement_20260524_191137.md

작성 일시: `2026-05-24 19:11:37 KST`

이 문서는 Coreline Auth v0.6 상용화 준비 중 `Async Postgres Adapter` 전환을 위한 첫 구현 범위를 고정하고, 기존 sync v0.5rc1 동작을 깨지 않기 위한 작업 문서다.

## 개발 목적
- 고부하 상용 환경에서 Postgres/connection pool 기반 인증 저장소를 붙일 수 있도록 async storage/service 경계를 신설한다.
- 기존 `CorelineAuthService`와 sync `AuthStorage`는 그대로 유지해 v0.5rc1 회귀를 막는다.
- 이번 배치는 실제 Postgres adapter 전 단계인 `AsyncAuthStorage` contract와 핵심 async auth flow 검증까지 구현한다.

## 개발 범위
- `AsyncAuthStorage` 프로토콜 추가.
- 테스트용 `AsyncMemoryAuthStorage` 추가.
- 핵심 인증 흐름용 `AsyncCorelineAuthService` 추가.
- FastAPI async JSON adapter의 최소 인증 route 추가.
- README / production roadmap 문서에 v0.6 async scaffold 상태 반영.
- 자체 테스트 추가 및 기존 `make test` 회귀 검증.

## 제외 범위
- 실제 SQLAlchemy/Postgres adapter 구현.
- Alembic migration 패키지 구현.
- 기존 sync service의 async 전환 또는 breaking change.
- board demo / admin UI의 async 전환.
- tenant/organization/billing 등 SaaS scope 확장.

## 최종 결과 요약
- Async contract/service/adapter scaffold와 Postgres SQLAlchemy Core adapter, Alembic migration scaffold가 추가됐다.
- 기존 sync `CorelineAuthService`와 SQLite/Memory storage는 breaking change 없이 유지된다.
- Postgres 실서버 연결 검증은 `CORELINE_AUTH_POSTGRES_DSN` 제공 시 자동 수행된다.
- 실제 DB 없이 검증 가능한 offline SQL migration과 atomic magic-link consume 회귀가 통과했다.
- 현재 Mac Docker 환경에서 임시 Postgres online migration/integration smoke도 통과했다.

## 잔여 리스크 / 후속 과제
- Admin/MFA/social 전체 async parity는 Postgres core adapter 안정화 후 단계적으로 확장한다.
- 실제 DSN 기반 Alembic online upgrade와 Postgres core flow는 운영 DB 준비 시 수행한다.
- Password-reset/OAuth state consume의 async parity와 원자적 consume은 해당 async flow 추가 시 강화한다.
