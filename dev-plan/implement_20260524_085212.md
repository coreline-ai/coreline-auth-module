# implement_20260524_085212.md

작성 일시: `2026-05-24 08:52:12 KST`

이 문서는 Coreline Auth를 독립 인증 모듈로 프로덕션화하기 위한 **보안·성능·운영 hardening 개발 계획**이다. 기존 v0.4 구현을 확장하되, CoreMCP 본체에 인증 SaaS 기능을 흡수하지 않는다.

## 개발 목적

Coreline Auth는 현재 v0.4 수준의 독립 인증 core와 SaaS형 데모를 갖췄다. 다음 단계는 새 기능을 무작정 늘리는 것이 아니라, 실제 서비스에 붙였을 때 문제가 되는 보안/성능/운영 구멍을 release gate로 정리하고 순서대로 닫는 것이다.

## 개발 범위

- Cookie 기반 web flow CSRF 통합
- Social/OIDC account linking 안전 정책 강화
- Password 변경/reset 이후 session revoke
- Login timing hardening
- Demo debug token/password 노출 guard
- SQLite concurrency/performance hardening
- Session touch write-throttle
- OIDC metadata/JWKS fetch/cache 검증 강화
- Persistent audit storage 및 audit viewer 권한 분리
- TOTP/MFA/AAL2 실제 동작으로 승격하기 위한 v0.5 계획

## 제외 범위

- CoreMCP 기본 인증 방식 교체
- team/workspace/organization/billing
- 모든 social provider 일괄 구현
- Redis/Postgres adapter 즉시 구현
- WebAuthn/passkey full implementation 즉시 구현
- 외부 LLM API 의존성

## 공통 진행 규칙

- `src/coreline_auth`는 `coremcp.*` 또는 `apps.api.coremcp.*`를 import하지 않는다.
- password/session/magic/reset/verification/provider token 원문을 DB/log/audit에 저장하지 않는다.
- 보안 phase는 regression test를 먼저 추가하거나 같은 phase 안에서 추가한다.
- demo 편의 기능은 명시적 demo mode에서만 허용한다.
- provider access/refresh token은 기본 미저장 정책을 유지한다.
- 각 Phase는 자체 테스트 완료 후에만 다음 Phase로 넘어간다.

## Phase 1. Security release gate

### 목표

실 배포 전 반드시 막아야 하는 cookie/auth/social/password lifecycle 보안 이슈를 닫는다.

### 구현 태스크

- [x] `CsrfProtector`를 FastAPI adapter와 demo form에 실제 연결한다.
- [x] Bearer-only JSON API는 CSRF opt-out 가능하게 하되, cookie session 사용 state-changing route는 기본 CSRF required로 둔다.
- [x] Social account linking은 provider identity 우선, verified email fallback only 정책으로 바꾼다.
- [x] `consume_password_reset()` 이후 해당 user의 기존 session을 revoke한다.
- [x] admin `set_user_password()` 이후 대상 user의 기존 session을 revoke한다.
- [x] user 없음/credential 없음 로그인 실패 경로에도 dummy Argon2 verify를 수행한다.
- [x] demo app의 owner password/debug magic/reset token 노출은 `CORELINE_AUTH_DEMO_MODE=true`일 때만 허용한다.
- [x] admin audit viewer 권한을 `users:read`가 아니라 `audit:read`로 분리한다.

### 자체 테스트

- [x] CSRF 없는 cookie POST는 403
- [x] Bearer API flow는 CSRF 없이 동작
- [x] unverified provider email은 기존 계정에 link되지 않음
- [x] password reset 후 이전 session은 invalid
- [x] admin password set 후 이전 session은 invalid
- [x] user-not-found login도 dummy verify 호출 회귀
- [x] demo mode off에서 debug token/password가 응답에 없음
- [x] audit viewer는 `audit:read` 없으면 403

### 완료 조건

- [x] phase 테스트 통과
- [x] 기존 `make test` 통과
- [x] 보안 리뷰 H-1~H-5 대응 완료

## Phase 2. SQLite/session performance hardening

### 목표

SQLite 기반 소규모 production/demo 운영에서 lock contention과 write amplification을 줄인다.

### 구현 태스크

- [x] `CorelineAuthConfig.session_touch_interval_seconds` 추가
- [x] `verify_session()`이 매 요청마다 DB write하지 않도록 throttle 적용
- [x] SQLiteAuthStorage에 `PRAGMA journal_mode=WAL`, `busy_timeout`, `foreign_keys=ON` 적용
- [x] SQLiteAuthStorage와 SQLiteBoardStorage에 `threading.RLock` 또는 명확한 connection access guard 적용
- [x] auth_sessions/auth_login_flows/auth_users 조회용 index 추가
- [x] expired login flow/session cleanup API 추가
- [x] admin list users를 storage-level filter + pagination으로 이동
- [x] rate limiter expired bucket cleanup 및 max bucket cap 추가

### 자체 테스트

- [x] session touch interval 내 verify는 update_session 미호출
- [x] interval 이후 verify는 idle ttl refresh
- [x] legacy SQLite bootstrap이 새 index/pragma와 호환
- [x] concurrent login/session verify smoke
- [x] admin list pagination/filter 결과 회귀
- [x] rate limiter bucket cleanup 회귀

### 완료 조건

- [x] phase 테스트 통과
- [x] 성능 리뷰 P-1~P-5 대응 완료 또는 명시 후속화

## Phase 3. OIDC/JWKS production hardening

### 목표

Google/OIDC connector를 실제 provider 환경에 붙일 때 필요한 metadata/JWKS 검증과 캐시 정책을 갖춘다.

### 구현 태스크

- [x] `OIDCMetadataClient` 추가: https-only, localhost dev 예외, timeout, content-type, max bytes
- [x] JWKS cache TTL + kid miss refresh 정책 추가
- [x] OIDC discovery fetcher에 allowed issuer host 또는 host allowlist option 추가
- [x] ID token `azp` 검증 추가 — multiple audience일 때 필수
- [x] ID token `nbf`, max token age option 추가
- [x] OAuth code exchange/userinfo response size cap과 token redaction helper 추가

### 자체 테스트

- [x] metadata non-https public issuer reject
- [x] metadata oversize reject
- [x] JWKS cache hit/kid miss refresh
- [x] multiple audience + missing/wrong azp reject
- [x] nbf future reject
- [x] max age exceeded reject
- [x] token response raw token이 audit/log/model에 저장되지 않음

### 완료 조건

- [x] phase 테스트 통과
- [x] Google/OIDC real credential smoke checklist 문서화
