작성 일시: `2026-05-23 22:35:00 KST`

이 문서는 Coreline Auth를 **프로덕션급 멀티 유저 인증/권한 모듈**로 끌어올리고, 게시판 수준의 실제 데모 앱으로 권한 자격을 검증하기 위한 개발 범위를 고정한다.

## 개발 목적

현재 Coreline Auth는 email/password, magic link, session, admin core, Google/Facebook connector skeleton까지 갖췄다. 하지만 “기본적으로 멀티 유저 권한까지 모두 포함된 인증 시스템”으로 보려면 다음이 더 필요하다.

- role/permission을 실제 resource/action/ownership 권한으로 표현
- 일반 사용자/작성자/관리자/모더레이터 권한 차이를 데모에서 확인
- Google/Facebook/OIDC production flow 강화
- production email, password reset, email verification
- MFA/passkey 확장을 수용할 구조
- 테스트/문서/릴리즈 체계

## 개발 범위

## 공통 진행 규칙

- 각 Phase는 앞선 Phase 자체 테스트 완료 후에만 진행한다.
- `src/coreline_auth`는 CoreMCP runtime code를 import하지 않는다.
- password/session/magic-link/provider token 원문 저장 금지.
- provider access/refresh token은 기본 미저장, vault opt-in만 허용.
- demo app은 core API를 사용하는 소비자 역할로 유지한다.
- 고급 기능을 추가하더라도 current email/password/magic-link 테스트를 깨지 않는다.
