이 문서는 Coreline Auth v0.1이 독립 실행 가능한 인증 core인지 확인하고, 모듈 자체 테스트를 실제 웹 SaaS 형태로 수행하기 위한 개발 범위를 고정한다.

## 개발 목적

Coreline Auth를 CoreMCP에 적용하기 전에, 모듈 자체가 다음을 만족하는지 검증한다.

- 독립 package로 import/test 가능
- email/password 로그인 가능
- magic link 로그인 가능
- session/permission/admin core 동작
- 실제 웹앱 형태로 login/logout/protected page 검증 가능
- 기존 오픈소스 auth 구현과 비교한 도입/미도입 사항 문서화

## 개발 범위

- `packages/coreline-auth` 독립 package 구현
- v0.1 core auth 구현
- FastAPI JSON adapter 구현
- SaaS-style demo webapp 구현
- 자동 테스트와 수동 테스트 문서 작성
- gap review와 reference comparison 문서 작성

## 제외 범위

- CoreMCP 적용 adapter
- Google/Facebook/OIDC production connector
- production email provider 연동
- full RBAC/admin UI
- team/workspace/billing/marketplace

## 공통 진행 규칙

- Coreline Auth source는 CoreMCP runtime code를 import하지 않는다.
- password/session/magic-link token 원문을 DB에 저장하지 않는다.
- demo webapp은 운영 제품이 아니라 자체 검증용이다.
- v0.2 범위는 이번 구현에 넣지 않는다.
