# implement_20260531_214223.md

작성 일시: `2026-05-31 21:42:23 KST`

이 문서는 `coreline-auth`에서 게시판 도메인을 새 폴더/패키지로 완전히 분리하기 위한 실행 계획이다. 병렬 에이전트 코드 분석 결과를 통합해, 인증 모듈은 어디서나 재사용 가능한 범용 모듈로 남기고 게시판은 독립 데모 제품으로 계속 고도화할 수 있게 작업 범위와 회귀 방지 기준을 고정한다.

## 개발 목적

현재 `coreline-auth` 내부 예제로 포함된 게시판 관련 코드와 테스트를 별도 `coreline-board` 폴더/패키지로 분리한다.

최종 상태:

- `coreline-auth`는 인증, 세션, 권한 엔진, CSRF, MFA, OAuth/OIDC, WebAuthn, storage, readiness만 제공한다.
- `coreline-auth`는 게시판 도메인 모델, 게시판 storage, 게시판 route, 게시판 seed, 게시판 demo, 게시판 permission vocabulary를 알지 않는다.
- `coreline-board`는 `coreline-auth`를 외부 인증 dependency로 사용한다.
- 의존 방향은 항상 `coreline-board -> coreline-auth` 단방향이다.
- 게시판은 계속 데모로 고도화될 수 있도록 독립 demo app, 독립 DB, 독립 layout, 독립 test suite를 가진다.

- 이 문서는 계획 문서이며 실제 코드 이동은 수행하지 않는다.
- 새 게시판 기능 추가는 하지 않는다.
- UI 리디자인은 하지 않는다. 단, layout 분리와 URL/CSRF/cookie 설정 주입 구조는 포함한다.

## 병렬 에이전트 코드 분석 요약

### Agent A — Domain / Storage 분석

- `board_models.py`는 `BoardPost`, `BoardComment`, `BoardPostDetail`만 포함한다.
- 모델 timestamp가 `coreline_auth.models.now_utc`에 의존한다.
- `board_service.py`는 session token을 받아 `CorelineAuthService.verify_session()`을 호출하고 `Principal.session.permissions`로 권한을 판단한다.
- `board_storage.py`는 `MemoryBoardStorage`, `SQLiteBoardStorage`를 제공하지만 실제 Protocol은 없다.
- `BoardService.storage` 타입은 `MemoryBoardStorage | None`인데 실제로는 `SQLiteBoardStorage`도 주입되므로 분리 시 `BoardStorageProtocol`이 필요하다.
- board storage는 `AuthValidationError`, `now_utc`, `to_iso`, `from_iso`에 의존한다.
- `coreline_auth.permissions`에 board 권한 vocabulary가 들어 있는 것이 가장 큰 core coupling이다.

### Agent B — Web / Demo / CSRF 분석

- `saas_app.py`가 auth demo이면서 board를 직접 import/mount한다.
- `mount_board_routes(prefix="/board")`가 있지만 내부 링크/form action이 `/board`, `/login`, `/logout`, `/admin`, `/`에 하드코딩되어 있다.
- board CSRF는 board router 자체가 아니라 `saas_demo/layout.py`의 hidden field 문자열 치환과 `demo_csrf_middleware()`에 의존한다.
- `saas_demo/layout.py`에 board CSS/menu/login link/role account sidebar가 섞여 있다.
- auth DB와 board DB가 같은 SQLite 파일을 공유한다.
- localhost에서 auth demo와 board demo를 동시에 띄우면 cookie name 충돌 가능성이 있으므로 board demo는 별도 cookie name을 써야 한다.

### Agent C — Auth Boundary / Tests 분석

- `src/coreline_auth/permissions.py`의 `RBAC_ROLE_PERMISSIONS`에 `board:read`, `post:*`, `comment:*`가 하드코딩되어 있다.
- `service.py`는 직접 board를 모르지만 `PolicyEngine.permissions_for()` 결과를 세션에 저장하므로 board 권한이 신규 세션에 섞인다.
- `authorization.py`와 `fastapi_adapter.py`는 범용으로 유지 가능하다.
- `tests/test_authorization.py`가 `board`, `post`, `comment` 리소스로 범용 권한 엔진을 테스트하고 있어 auth 테스트가 board 도메인에 오염되어 있다.
- `tests/test_board_service.py`, `tests/test_board_persistence.py`, `tests/test_demo_board_webapp.py`는 전부 `coreline-board`로 이동 대상이다.
- 분리는 현재 WIP가 아니라 마지막 커밋 HEAD(`4a211f9`) 기준의 별도 worktree에서 시작하는 것이 안전하다.

## 문서 기반 제약 사항

- `src/coreline_auth`는 `coremcp.*` 또는 `apps.api.coremcp.*`를 import하지 않는다.
- `coreline-auth`는 CoreMCP 하위 기능이 아니라 독립 인증 모듈이다.
- `coreline-auth`는 `coreline-board`를 import하지 않는다.
- `coreline-auth`는 board permission vocabulary를 기본 정책에 포함하지 않는다.
- password/session/magic-link token 원문을 DB/log/audit에 저장하지 않는다.
- 게시판은 auth token 원문을 저장하지 않는다.
- 게시판은 auth user 전체를 복제하지 않고 `author_user_id` 등 최소 참조만 저장한다.
- 자체 암호 알고리즘을 만들지 않는다.

## 공통 진행 규칙

- 현재 작업트리 WIP는 보존한다. `git reset --hard` 금지.
- board 분리는 마지막 커밋 HEAD 기준 별도 worktree에서 시작한다.
- 보안 hardening WIP와 board extraction diff를 한 커밋/PR에 섞지 않는다.
- 각 Phase는 앞선 Phase 자체 테스트 완료 후에만 시작한다.
- 테스트 실패 시 다음 Phase로 넘어가지 않는다.
- 임시 compatibility shim을 만들면 제거 Phase와 만료 조건을 문서화한다.
- auth package에서 board를 다시 import하는 방식의 compatibility는 금지한다.

권장 명령:

```bash

git worktree add -b split-board-from-head ../coreline-auth-board-split 4a211f9
```

작업 방식:

1. `../coreline-auth-board-split`에서 board extraction을 수행한다.
2. `../coreline-board`를 새 패키지로 만든다.
3. 현재 WIP에서 필요한 항목만 나중에 선별 port한다.

선별 port 후보:

| 현재 WIP 항목 | board split 필요도 | 처리 |
|---|---:|---|
| `permissions.py` AUTHZ-001 scoped wildcard fix | 높음 | auth hardening 커밋으로 별도 반영, board 테스트는 generic 권한과 board 권한 양쪽에서 검증 |
| `board_seed.py` `revoke_sessions=False` | 중간 | 새 board seed에서 최신 auth API에 맞게 반영 |
| `fastapi_adapter.py` CSRF fail-closed | 중간 | board demo CSRF 설계의 dependency로 소비, 코드 복사 금지 |
| `saas_app.py` OIDC/CSRF changes | 낮음 | auth demo 전용. board extraction에 섞지 않음 |
| MFA/OIDC/WebAuthn/storage hardening | 낮음 | board package에는 복사하지 않고 auth dependency 요구 버전으로 관리 |
| 스킬/HTML/문서 산출물 | 없음 | board split과 분리 |
