1인증 운영 세트

Coreline Auth는 인증 운영 세트입니다.

서비스 사용자는 가입, 로그인, 비밀번호 재설정, 세션 관리 화면을 쓴다. 관리자는 사용자, 권한, 감사 로그를 운영한다. 개발팀은 FastAPI 앱에 인증 라우트를 붙여 제품형 인증 흐름을 빠르게 시작할 수 있다.

For users

가입·로그인·계정 관리

이메일/비밀번호, 매직 링크, 소셜 로그인, 비밀번호 재설정, 세션 확인 같은 일반 사용자 흐름을 제공한다.

For admins

사용자·권한·감사 관리

관리자는 사용자 상태, 역할, 세션, 감사 로그를 대시보드와 API로 관리한다.

For ops

운영 준비도와 이메일 확인

시스템 readiness, 이메일 outbox, provider 준비 상태를 화면에서 점검할 수 있다.

핵심: 로그인 페이지가 아니라 인증 운영 세트사용자 화면, 관리자 화면, 운영 점검 화면까지 한 번에 제공하는 Python 인증 모듈이다.
사용자 관점

계정 생성부터 보안 확인까지

로그인, 가입, 매직 링크, 비밀번호 재설정, 소셜 로그인, 계정 보안, 세션, 활동 내역 화면이 준비되어 있다.

관리자 관점

사용자와 권한을 운영

관리자 콘솔에서 사용자 목록, 역할 분포, 사용자 상세, 상태 변경, 세션 회수, 감사 로그 조회를 다룬다.

운영 관점

배포 전 상태 점검

system readiness, provider readiness, email outbox와 템플릿 preview로 운영 준비 상태를 확인할 수 있다.

2기능 지도: 인증·계정·관리·운영을 한 묶음으로 제공

Coreline Auth의 기능은 크게 네 층으로 볼 수 있다. 첫째, 사용자가 직접 만나는 로그인/가입/재설정 흐름이다. 둘째, 계정 보안과 세션 관리처럼 사용자가 스스로 계정을 관리하는 영역이다. 셋째, 관리자 콘솔에서 사용자와 권한을 운영하는 영역이다. 넷째, 운영자가 배포 전 상태와 이메일 발송 준비도를 점검하는 영역이다.

Feature Explainer

Coreline Auth는 무엇을 해주나

개발자가 인증을 처음부터 다시 만들지 않고, 제품에 필요한 사용자 로그인·계정 보안·관리자 운영 흐름을 빠르게 붙일 수 있게 해준다.

TL;DR

사용자에게는 안전한 로그인 경험을, 관리자에게는 사용자·권한·감사 도구를, 운영자에게는 readiness와 이메일 점검 화면을 제공한다.

01 사용자가 바로 쓰는 기능

회원가입, 로그인, 매직 링크, 비밀번호 재설정, 소셜 로그인, 로그아웃 같은 기본 인증 화면을 제공한다.

  • 이메일 + 비밀번호 로그인
  • 비밀번호를 잊었을 때 재설정
  • Google/Facebook/OIDC 소셜 로그인 연결
  • 본인 세션 확인과 직접 로그아웃
02 보안을 높이는 기능

사용자는 계정 보안 화면에서 MFA 상태, 세션, 활동 내역을 확인할 수 있고, 서비스는 CSRF·세션 만료·비밀번호 변경 시 세션 회수 같은 기본 안전장치를 제공한다.

  1. 1로그인 후 계정 보안 화면으로 이동
  2. 2활성 세션과 최근 활동 확인
  3. 3필요하면 세션을 직접 종료하거나 비밀번호를 변경
03 관리자가 쓰는 기능

관리자는 사용자 목록, 사용자 상세, 역할 변경, 계정 비활성화/활성화, 세션 회수, 감사 로그 확인을 한 흐름에서 처리한다.

  • owner/admin/viewer/user 역할 기반 접근
  • 사용자 상태와 세션 관리
  • 관리자 작업에 대한 감사 로그 조회

처음 써보는 순서

uv add coreline-auth
uv sync --extra postgres  # Postgres 어댑터가 필요할 때
make run-demo
# http://127.0.0.1:8010/login
# demo: owner@example.com / coreline-demo-password
mount_auth_routes(app, auth, csrf_protector=csrf, secure_cookies=True)
mount_admin_routes(app, auth, csrf_protector=csrf)

3기술 스택 전체 지도: Python 인증 모듈을 제품형 운영 표면으로 확장한다

4아키텍처 심화 분석: 서비스 코어와 어댑터를 분리한 플러그형 구조

README의 architecture 흐름과 소스 트리는 같은 방향을 가리킨다. 브라우저/API 요청은 FastAPI adapter를 통과하지만, 인증 판단의 중심은 framework-agnostic CorelineAuthService다. 저장소, 이메일, rate limiter, MFA vault, metric sink는 protocol로 갈라지고, SQLite/Postgres/Redis/SMTP/Prometheus 같은 실제 구현은 바깥 adapter로 붙는다.

ADAPTER

FastAPI는 입구

mount_auth_routes, mount_admin_routes, dependency helper가 HTTP/cookie/CSRF 접점을 담당한다. 저장소별 로직은 이 층에 두지 않는 패턴이다.

SERVICE

인증 판단은 코어 서비스

CorelineAuthService가 로그인, 세션 발급/검증, magic link, password reset, MFA, social login, audit를 조율한다.

PROTOCOLS

교체 가능한 운영 부품

Storage, EmailSender, RateLimiter, MfaVault, MetricSink가 protocol 성격으로 분리되어 테스트/SQLite/Postgres/Redis/SMTP 조합을 바꿀 수 있다.

BOUNDARY

호스트 앱과 단방향 의존

AGENTS와 Makefile은 CoreMCP/Coreline host import가 src/coreline_auth 안으로 들어오지 않도록 import guard를 둔다.

OPERATIONS

readiness와 smoke가 운영 감각을 만든다

readiness-check, smoke-demo-secure, postgres-smoke target이 실제 배포 전 점검 흐름을 제공한다.

UNKNOWN

실제 배포 토폴로지는 확인 필요

이 HTML은 저장소 구조 분석이다. 운영 환경의 Redis/Postgres/SMTP/OIDC provider 실제 연결 상태는 사용자 환경에서 별도 확인해야 한다.

5디렉토리 구조 해부: core, adapter, demo, proof가 분리되어 있다

디렉토리는 기능 이해에도 도움이 된다. src/coreline_auth는 제품 모듈 본체이고, storage/와 social/은 교체 가능한 세부 영역이다. examples/saas_app.py와 demos/board_rbac/는 실제 화면/호스트 앱 검증을 담당하고, tests/와 Makefile은 기능이 문서에 머물지 않도록 회귀 확인을 맡는다.

6사용자 기능: 가입부터 세션 종료까지 한 흐름으로 이어진다

서비스 사용자가 체감하는 핵심은 복잡한 보안 용어가 아니라 “계정에 안전하게 들어가고, 문제가 생기면 스스로 복구하고, 내 로그인 상태를 확인할 수 있는가”다. 이 저장소는 로그인 화면만이 아니라 가입, 비밀번호 재설정, 매직 링크, 소셜 로그인, 내 계정, 보안, 세션, 활동 내역 화면까지 포함한다.

가입

새 계정 만들기

사용자는 이메일과 비밀번호로 가입하고, 서비스 정책에 따라 이메일 검증 또는 역할 기반 접근 흐름으로 이어질 수 있다.

로그인

여러 로그인 방식

기본 이메일/비밀번호 외에도 매직 링크, Google/Facebook/Generic OIDC 흐름을 연결할 수 있다.

복구

비밀번호 재설정

비밀번호를 잊었을 때 reset flow를 통해 계정 복구를 진행하고, 성공 시 기존 세션을 회수하도록 설계되어 있다.

내 계정

프로필과 보안 상태

사용자는 본인 프로필, 계정 보안, 활성 세션, 최근 활동을 확인할 수 있다.

세션

내 로그인 관리

현재 로그인 상태와 과거 세션을 보고 필요하면 직접 세션을 종료할 수 있다.

로그아웃

안전한 종료

로그아웃 확인 화면과 세션 revoke 흐름을 통해 계정을 닫는 경험도 제공한다.

8관리자 기능: 사용자·권한·세션·감사 로그를 운영한다

관리자 입장에서 중요한 것은 인증 알고리즘보다 “사용자 문제가 생겼을 때 무엇을 할 수 있는가”다. Coreline Auth는 관리자 콘솔과 관리자 API를 통해 사용자 조회, 역할 변경, 비활성화/활성화, 비밀번호 설정, 세션 회수, 감사 로그 필터를 제공한다. 특히 self-ban과 last-owner lockout 보호를 문서화하고 있어, 관리자가 실수로 마지막 관리자 권한을 잃는 상황을 피하려는 설계가 보인다.

9시작 방법: 데모로 먼저 보고, 그 다음 앱에 붙인다

기능을 파악하는 가장 쉬운 순서는 데모 앱을 먼저 실행해 화면을 본 다음, FastAPI 앱에 인증 라우트를 붙이는 것이다. README 기준 데모는 make run-demo로 실행하고 http://127.0.0.1:8010/login에서 확인한다. 실제 제품 연결은 storage, auth service, csrf protector를 만들고 mount_auth_routes, mount_admin_routes를 붙이는 흐름이다.

10어디에 잘 맞나: FastAPI 기반 SaaS·관리자 도구·내부 서비스

이 모듈은 모든 서비스에 무조건 맞는 범용 로그인 위젯은 아니다. 가장 잘 맞는 곳은 Python/FastAPI 기반이고, 사용자 계정과 관리자 운영 기능을 빠르게 갖춰야 하며, 계정 보안과 감사 로그를 중요하게 보는 서비스다. 예를 들어 개인 SaaS, 내부 운영 도구, 관리자 대시보드, Coreline 계열 서비스처럼 인증을 여러 프로젝트에서 재사용하고 싶은 경우에 적합하다.
